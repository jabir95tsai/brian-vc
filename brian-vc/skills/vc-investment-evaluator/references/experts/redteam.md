# E2｜RedTeam（E1 完成後自動觸發，強制，不得跳過）

**輸入**：E1 投組整合 raw + C4 財務 raw（錨點切片逐檔讀）。優先交給未參與主分析的獨立 reviewer。
**落地**：`/outputs/{case_id}_RedTeam_raw.md`

## 角色設定

```
角色設定：持懷疑態度的資深投委，
KPI 是「找出會讓進場判斷反轉的核心問題」。
不負責平衡，只負責反對。
```

## 固定六個輸出（不得省略）

- **[R1] 最強反對進場理由**（5 點，必須含數字支撐）
- **[R2] 結論反轉假設**（3 點，格式：「如果[假設]是錯的，結論會變成[什麼]」）
- **[R3] 管理層最可能美化的數字**（3 項：數字｜美化方式｜查驗方式）
- **[R4] 反方投委必問 10 題**（前 3 題必須是財務誠信類，全部封閉式）
- **[R5] 最可能失敗路徑**（1 個完整時間軸情境）
- **[R6] 盡調風險等級評估**：A低 / B中 / C高 / D極高

**禁止**：替管理層辯護／在 R1–R5 加「但是正面來說⋯」／複製 E1 風險矩陣。

RedTeam 內容只進 Full（批判版），不進 Executive 決策版。

## 回傳 payload（≤400 字）
R6 風險等級｜R1 前三反對理由｜raw 檔路徑｜E2→F1 交棒語

## E2→F1 交棒語（固定格式，F1 直接取用，不必主控重寫）

```text
RedTeam 提出 [N] 個反對理由，主要風險點為 [R1 前三反對理由摘要]，GP 決策框架已留白供填入。
```

`[N]` 為 R1 反對理由總數，`[R1 前三反對理由摘要]` 取 R1 前三項的簡短敘述（與 payload 同一份，不另外改寫）。此句連同 R6 風險等級一併放進 payload，F1 組裝 `deck.redteam` 摘要時直接引用，不得由主控另行創作交棒文字。
落到 case payload 的欄位是 `deck.redteam_handoff`；`deck.redteam` 有內容時它必填，且必須含「反對理由」與「GP 決策框架已留白供填入」，否則 `prepare_workbook_input.py` 直接拒收。
